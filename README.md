# LeadHunter

ИИ-агент, который круглосуточно ищет работу для веб-разработчика и присылает лиды в Telegram.
Сам он ничего не пишет клиентам: только находит, проверяет и объясняет, что нашёл и почему это стоит внимания.

## Что ищет

**Компании с плохими сайтами.** По нишам и городам (стоматологии Казани, автосервисы Москвы…) берёт компании
из OpenStreetMap, 2ГИС и Яндекс Карт, проверяет сайт и присылает короткую карточку в три строки:

```
🏚 Стоматология Улыбка · 84/100
Казань · стоматология · ул. Баумана, 12

Частная клиника на три кресла, работает с 1998 года
Сайт из 2014 года, не открывается на телефоне
🔗 ulybka.ru
• нет мобильной версии
• Flash-баннер
• © 2014
🔧 Редизайн и мобильная версия
📞 +7 900 000-00-00 · info@ulybka.ru
```

Кнопка «Подробнее» дораскрывает остальное прямо в том же сообщении: все найденные проблемы,
технологии сайта, почему оценка такая и как лид нашёлся. «Открыть» ведёт на сайт.

Компании без сайта (только VK, Taplink, yclients) тоже приходят, как отдельный тип лида.

**Прямые заказы.** Telegram-чаты и каналы с заказами, hh.ru (проектная работа), свои RSS-ленты по желанию.
Фриланс-биржи по умолчанию выключены.
Префильтр по ключевым словам отсекает мусор, затем модель отделяет настоящие заказы от самопиара
исполнителей и присылает: что нужно, бюджет, срок, контакт, почему подходит, ссылку.

## Управление

Всё основное — кнопками, команды дублируют их.

- Меню снизу: **Статистика**, **Сводка**, **Источники**, **Правила**, **Проверить сайт**, **Ещё**.
- «Ещё» открывает разбор итогов, пороги (кнопки −/+), добавление ниши, города, чата, парсер и паузу.
- Где нужен текст (адрес сайта, ниша, город, чат), бот спрашивает и ждёт ответ следующим сообщением.
- В «Источниках» каждый источник выключается и включается кнопкой, в «Правилах» директива удаляется кнопкой.
- Сводка приходит списком кнопок: нажал — открылась карточка.
- Любой другой текст по-прежнему становится директивой навсегда.

## Как учится

Под каждым лидом кнопки **Мусор / Интересно / Взял / Сделка**. Это главный сигнал.

1. **Память.** Все лиды и оценки хранятся в SQLite (`data/leadhunter.db`).
2. **Выбор, где искать.** Каждая пара «ниша × город» и каждый источник заказов — это «рука» многорукого бандита
   (Thompson sampling). Ниши, где ты жмёшь «Взял», получают больше бюджета на поиск; где жмёшь «Мусор» — меньше.
   Новые ниши всегда получают шанс, поэтому агент продолжает исследовать.
3. **Примеры.** В каждую оценку подмешиваются последние понравившиеся и забракованные лиды.
4. **Ежедневный разбор (23:00).** Модель смотрит статистику и оценки за день и сама:
   переписывает правила оценки, добавляет новые ниши (с OSM-тегами), отключает источники, которые дают только мусор,
   правит ключевые слова префильтра, добавляет запросы для hh.ru и для поиска новых Telegram-чатов.
   Правила хранятся по версиям, `/rollback` откатывает.
5. **Пороги.** Если среди отправленного много мусора — порог мгновенной отправки растёт, если мало — падает.
   То, что ниже порога, приходит одной вечерней сводкой.
6. **Без спама.** Не больше `max_alerts_per_hour` мгновенных уведомлений в час (по умолчанию 4),
   остальное уходит в вечернюю сводку.
7. **Директивы.** Любое сообщение боту без «/» — постоянное правило с высшим приоритетом.
   Например: «не присылай салоны красоты», «бюджет меньше 10к не интересен», «ищи только в Казани».
8. **Поиск новых чатов (12:00).** Ищет публичные Telegram-чаты с заказами и предлагает кнопкой «Читать @чат».

Чтобы через неделю агент работал стабильно, оценивай ~10–20 лидов в день. Без оценок учиться не на чем.

## Сколько стоит

- Модель `gpt-6-luna`: $0.10 за 1M входящих токенов, $0.50 за 1M исходящих. Аудит одного сайта ≈ 3–4 тыс. токенов,
  пачка из 8 постов ≈ 5 тыс. Итого при ~1000 сайтов и ~1500 постов в день — **примерно $0.5–1 в день**.
  Лимит расходов — `DAILY_BUDGET_USD` (по умолчанию $1 в день), `/stats` показывает расход.
- VPS: от ~$5 в месяц (1 vCPU, 1 ГБ RAM хватает; со скриншотами лучше 2 ГБ).
- OSM, hh.ru, Telegram — бесплатно. 2ГИС и Яндекс — по их тарифам, они опциональны.

## Установка

Нужен Python 3.11+ и сервер, который работает круглосуточно.

```bash
git clone <repo> /opt/leadhunter && cd /opt/leadhunter
```

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

```bash
cp .env.example .env && cp config.example.yaml config.yaml
```

### Ключи в `.env`

| Переменная | Где взять | Обязательно |
|---|---|---|
| `OPENAI_API_KEY` | platform.openai.com → API keys | да |
| `OPENAI_MODEL` | по умолчанию `gpt-6-luna`; точное имя проверь в доках OpenAI, `check` покажет, работает ли | да |
| `TELEGRAM_BOT_TOKEN` | @BotFather → /newbot | да |
| `TELEGRAM_OWNER_ID` | запусти агента, напиши боту `/start`, он пришлёт id | да |
| `TG_API_ID`, `TG_API_HASH` | my.telegram.org → API development tools. Нужны, чтобы читать Telegram-чаты | нет, но очень желательно |
| `TWOGIS_API_KEY` | dev.2gis.com | нет |
| `YANDEX_PLACES_API_KEY` | developer.tech.yandex.ru, «API Поиска по организациям» | нет |
| `PAGESPEED_API_KEY` | Google Cloud Console → PageSpeed Insights API | нет, но без ключа Google часто отвечает 429 |
| `OPENAI_BASE_URL` | если ходишь через прокси или OpenRouter | нет |
| `LLM_VISION=1` | вместе с `audit.screenshot: true` модель видит скриншот сайта | нет |

### Свой парсер 2ГИС как инструмент модели

Если на сервере есть парсер, который достаёт из 2ГИС компании без сайта, агент может вызывать его сам,
но только когда это нужно: на ежедневном разборе модель видит, как заходят лиды «нет сайта» по нишам,
и решает, по какой нише и городу запустить парсер и сколько взять. Ограничения — дневной лимит и лимит на запрос.
Вручную: `/parse стоматология | Казань 30`.

В `config.yaml`:

```yaml
parser:
  enabled: true
  command: "python3 /opt/2gis-parser/main.py --query {niche} --city {city} --limit {limit} --json"
  workdir: /opt/2gis-parser
  daily_limit: 300
  per_request_limit: 50
```

Плейсхолдеры `{niche}`, `{query}`, `{city}`, `{limit}` подставляются отдельными аргументами, без shell.
Парсер должен печатать в stdout JSON-массив, JSON-строки или CSV. Поля узнаются автоматически
(`name`/`название`, `phone`/`телефон`, `address`/`адрес`, `rubric`/`категория`, `site`/`сайт`, `id`);
нестандартные имена задаются в `parser.fields`, например `fields: {name: [firm_title]}`.
Пользователь `leadhunter` должен иметь права на запуск парсера.

## Настройка

Всё в `config.yaml` (неуказанное берётся по умолчанию из `leadhunter/settings.py`):
города, ниши, расписание, пороги, источники, ключевые слова. Пороги и ключевые слова читаются из конфига
только при первом запуске, дальше живут в базе: агент сам их подстраивает, а вручную меняются через `/threshold`.
Новые города, ниши, чаты и RSS из конфига подхватываются при каждом запуске. Список ниш с готовыми OSM-тегами — `NICHE_TAGS`
в `leadhunter/discovery.py`. Для своей ниши без OSM-тегов поиск идёт через 2ГИС или Яндекс (если есть ключи),
либо агент сам предложит теги на ежедневном разборе.

## Ограничения и правила

- Агент берёт данные только из открытых API и RSS, сайты компаний проверяет по одной главной странице, честно
  представляется (`LeadHunterBot`) и соблюдает `robots.txt`.
- Kwork и подобные площадки без открытого API/RSS не парсятся.
- Связываешься с компаниями ты сам и адресно. Массовые рекламные рассылки без согласия в РФ запрещены (38-ФЗ).
